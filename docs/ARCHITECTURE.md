# Architecture map

Repository entry and run instructions live in `README.md`; dependency declarations and Python support live in `pyproject.toml`, and resolved versions live in `poetry.lock`. This map describes the code and operational paths. The repository has no local `AGENTS.md` or decision log.

## Structure

`main.py` starts `app.web`, which calls `app.production.VideoAnalyzer`. The analyzer uses `app.audio` for transcription and speaker analysis, `app.video` for face and frame work, and `app.utils` for media helpers. Imports point from the web entry toward production and its audio/video helpers.

## Operation

`Dockerfile` builds from Python 3.10 and installs Poetry dependencies from `pyproject.toml` and `poetry.lock`. `docker-compose.yml` runs the Streamlit command and requests a GPU. `tests/` contains executable scripts that use local media or downloaded models at import time; they are not an isolated automated test suite. The repository has no CI workflow.

## Rationale

`onnxruntime` is constrained in `pyproject.toml` because the RealTimeSTT dependency uses it and the Docker Python 3.10 environment needs a compatible Linux wheel. `setuptools` stays below 82 because `face-recognition-models` imports `pkg_resources`. Keep the lockfile generated by Poetry so the manifest and resolved graph stay in agreement.
